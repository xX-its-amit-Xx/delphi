The DELPHI kernel

A design is only as good as the records under it. This page shows a small trusted core that will not hand over a file unless every number in it traces back to a paper that printed it, and every law it was checked against has been accepted by the Lean proof kernel. When something is missing, it says so and names what would fix it, instead of filling the gap with a plausible guess.

An independent research project. Everything here is a design: nothing has been built, cloned, sequenced, or run on a robot.

A number cannot enter without the sentence it was read in and where that sentence sits in the paper.

"Cannot tell" is an answer

A missing input never becomes a pass. It becomes cannot-assess, with the reason attached.

Refusals are the product

Each refused artifact is a short list of measurements that would unblock it. That list is what you send an author.

Nothing edits silently

Every record is named by the hash of its own contents and chained to the one before. Change a number and its name changes.

Use it in your own project a command-line toolset, a cookbook and a film

The kernel now comes as a command, delphi, that you run inside a repository that already exists. One command adds a small folder holding the project's record. After that there is one command for each thing the method asks of you: write down a source and the words you read in it, write down the number, record a checked statement, apply it, and ask for the result — which you get only if everything under it held.

The film replays a real session: 26 commands run on a public repository, fractastical/morpholib, at one named commit. Three of its Lean files each say they contain no sorry. The run found that this is true of all 115 theorems, and that none of the three files could have shown it as published, because none asks Lean to print the axioms its theorems rest on. Nothing was pushed to that repository. Silent by design; tracks/video/cli-graph.py --check fails if a figure stops resolving.

What do the commands look like? 
delphi init                       add a .delphi/ folder to this repository; nothing else changes
delphi evidence --kind doi --ref … --quote "…" --where "…"
delphi fact --quantity … --value … --unit … --condition k=v --evidence <id>
delphi audit File.lean            copy a Lean file with one axiom-audit line per theorem added
delphi law --name … --informal "…" --lean File.Audited.lean
delphi verdict --law <id> --fact <id> --requires … --expr "…"
delphi build --artifact "…" --verdict <id> --file out/thing
delphi verify   delphi doctor     the two to put in CI
delphi why <name>                 walk a result, or a refusal, back to the words it rests on
What is the "private knowledge graph"?

Every command that records something rewrites a small page and two data files inside the project, so the project always has a current, linkable picture of what it has checked and on what grounds. "Published" here means published into the project's own folder. The tool opens no network connection and contacts no registry; sending anything to an outside registry stays a person's decision. Open the graph the recorded run produced.

How do I know the tool itself is sound?

It is tested the way the rest of this work is: a correct sequence must go through untouched, and then one deliberate mistake is injected at a time — a missing quote, a number typed as a phrase, a proof file with no audit, an output edited after it was recorded — and every one must be caught. 28 are injected and none survives. The method document is generated from the kernel's own checks, and its build fails if it states a rule nothing enforces.

What the run said a two-input AND, compiled from behaviour into DNA

The design is three lines of behaviour: assign out = a & b;. A transcriptional gate inverts, so an AND cannot be one gate — it becomes the NOR of two inverted inputs, which needs three repressor proteins that do not interfere with one another, each with enough separation between its output levels and the next gate's switching point.

Auditing a "0 sorry" claim why a true claim can still be uncheckable

Every formal-biology project says its proofs are machine-checked with no gaps. You cannot tell from a file that never asks the prover to print what each theorem rests on. Three different things can be true of such a file: the proofs are fine and nobody can tell; a gap is in there and the prover only warned about it; or a result was simply assumed, which passes any search for the word "sorry".

So we add one audit line per theorem to a copy and run the strict checker over both. Run against another project's 76-theorem file, at a pinned commit, on 2026-11-19:

as published     REJECTED  no axiom audit (76 of 76 theorems have no audit line)
with audit added CHECKED   axioms [Classical.choice, Quot.sound, propext]

The claim was true and not checkable from what had been published. Seventy-six added lines make it checkable. That is a contribution to offer upstream, not a criticism.

What this still does not say: that a theorem is the right theorem. A proof whose assumptions contradict each other is valid and says nothing, and no script catches that — it needs a reader.
